# Presentation style reference

Read themes.md, layouts.md, image-prompts.md and the style guidance in SKILL.md. Pages are composed from the recipes in `style-kit.json`, whose `contentCSS` already carries the style rules a deck needs, and the shared runtime renders every page as a fixed 1280x720 card. `style-source.css` preserves the original presentation stylesheet, including embedded font data where present. It is design-reference data only: palette, typography, spacing, page treatments and decorative geometry. Do not load its global or navigation selectors into the shared editor; carry any further rule you need into the scoped presentation model or node styles.

HTML snippets in the layout documentation only demonstrate content geometry; every page is built as independently editable containers and leaves through the style kit. `example-project.json` is a small English schema fixture containing only generic text plus this style's palette and typography. It contains no case artwork, real example prose or full case stylesheet and must not be delivered as a finished demo. Use the user's approved project data and these style rules to build a real presentation. Generated local examples are kept outside the installation ZIP.

Fonts are presentation assets: they are embedded in the style or fall back to system fonts, and the runtime adds Chinese, Japanese and Korean system fallbacks. Do not add webfont links. Confirm native font availability separately before claiming identical PowerPoint/Keynote wrapping. Never flatten meaningful copy into a picture merely to retain the font.
